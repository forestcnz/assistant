# 应用变速

适用于 Android 10 及以上、未 Root 的手机。入口为「设置 → 应用变速」。从手机上可启动的应用中选择目标，不固定任何应用包名；系统应用会显示不可替换的原因。搜索支持名称和包名。

## 使用

1. 选择目标应用与倍率。可只加速界面动画，或同时启用本地计时加速。
2. 点「生成变速安装包」。助手在私有目录备份原版 APK 与全部分包，再加入变速模块、签名并验证。失败不会替换已有备份索引。
3. 使用目标应用自身的功能备份数据。助手备份的是安装包，不能读取其他应用的账号、存档等私有数据。
4. 按需卸载原版，再点「安装变速版」。安装由 Android 系统确认；首次需要允许助手安装应用。卸载目标后，其备份条目仍保留在列表中。
5. 安装后选择倍率，点「应用倍率设置」；也可点「悬浮调速并打开应用」。悬浮面板可切换倍率，1× 恢复正常。关闭面板会保留当前设置。
6. 恢复原版时，可卸载变速版，再安装备份的原版。原版安装包不包含之前的本地数据。

## 实现与兼容范围

- 采用补丁安装，不包含完整 Android 沙箱。目标 APK 的包名、应用类及已有资源索引保留，新增独立 DEX、初始化 Provider 和 Frida Gadget。基础包和分包使用同一个独立补丁签名；不使用助手的正式发布密钥给第三方应用签名。
- 运行模块依赖 Frida Gadget 17.26.2 与 frida-java-bridge 7.0.13。支持 armeabi-v7a、arm64-v8a、x86、x86_64。下载文件在 payload-lock.json 中固定 SHA-256；手机使用时无需下载模块。
- 界面动画通过目标进程内的 ValueAnimator 倍率控制。原生计时拦截目标 APK 自身 native 库调用的 clock_gettime 单调时钟；系统框架、其他应用及日期时钟不作修改。倍率切换维护连续时间轴。
- 不保证自绘动画、Compose、WebView、独立子进程、直接系统调用或其他计时方式都能加速。服务端控制的等待不受本地变速影响。不同来源的计时混用可能不兼容；可关闭「同时加速本地运行节奏」后重试。
- 补丁不包含签名校验绕过或运行环境校验绕过。拒绝重新签名或不接受加载模块的应用可能无法运行。
- IPC 校验调用方包名及助手的签名证书。目标中保存上次倍率。助手更换签名、清除数据或卸载后，可能需要重新生成补丁。
- 模块加载失败会记录状态并继续目标应用启动；页面区分安装包生成、模块连接和实际计时命中，不能将模块连接等同于所有动画已加速。

## 构建与验证

原 Android 构建环境外，还需 Node.js 20.11+、npm 和 Python 3。Windows 可用 SPEED_PYTHON 指定 Python 可执行文件。Gradle 自动执行 npm ci、脚本打包、独立运行模块构建和固定版本 Gadget 下载。首次构建需联网；压缩下载缓存在根 build/speed-downloads 下。

- `gradle assembleDebug`：生成助手 APK，内置四种架构运行模块。
- `gradle testDebugUnitTest`：包括真实 APK 的 Manifest 改写、资源保持、原生库对齐和重新签名验证。Android SDK 的 aapt2 独立检查改写后的 Manifest。
- 在 tooling/speed-runtime 下运行 `npm test`：验证不同计时域、倍率切换与恢复 1× 的连续性，以及非法倍率拒绝。

这些检查不替代 Android 真机上的补丁安装、模块加载和实际动画效果验证。
